# 전력·안정성 검증 기록

목표: IMU/온도/심박/GPS의 BLE 전송 및 9600 USB 시리얼 디버깅을 유지하면서 안정성과 코드 품질을 개선하고 시스템 전력 소모를 줄인다.

## 현재 확인한 근거

- 실제 사용 코어: Adafruit nRF52 1.7.0. RTOS tick은 1024Hz, 기본 BLE 최대 대역폭 설정은 MTU 247 / event length 125ms였다.
- 프로젝트 패킷은 최대 20바이트이므로 MTU 23으로 전송 가능하다.
- ST LSM6DS3TR-C 데이터시트 CTRL6_C bit4 / CTRL7_G bit7로 고성능 모드를 끄고 52Hz ODR을 선택하면 저전력 모드가 된다. 주파수/설정 read-back 검사를 포함한다.
- 500Hz 주기를 2/3 RTOS tick으로 분배하는 코드에 대해 500,000개 연속 예약의 누적 tick 값을 검사한다.
- I2C STOP에서 SDA/SCL 해제를 확인하고 실패를 전달한다. 클록이 고정된 동안 RTOS 대기를 사용하여 5ms 제한 시간 내내 CPU를 소모하지 않는다. 호스트 테스트는 정상 ACK/read/repeated-START, STOP 실패, 이후 재시도를 포함한다. 실제 배선의 신호 검증과는 별개이다.
- C++ ASan/UBSan 테스트 및 Python 프로토콜/수신기 테스트가 있다. 이들은 물리적인 전류, RF 거리, 버스 신호 품질, 센서 정확도를 증명하지 않는다.

## 실물 검증에 필요한 것

NU40와 센서 배선, GPS 모델/사양, PC BLE 어댑터, 보드 전원 경로의 전류 측정이 필요하다. 현재 개발 환경에서 `/dev/ttyACM*`와 `/dev/ttyUSB*`가 발견되지 않았다. 보드 업로드와 실제 데이터 수신/전류 검증은 미완료이다.

## 측정 조건

동일한 전원 전압, 센서 구성, GPS 수신 환경, BLE 거리/PC, 펌웨어 데이터 주기를 고정하고 비교한다. 전류계 삽입 시 USB와 배터리 중복 급전으로 측정 경로를 우회하지 않도록 한다. 짧은 순간 값 대신 최소 60초 구간의 평균/최대 전류와 실제 데이터 수신율을 함께 기록한다.

## 남은 검증과 개선

1. 실제 보드에 업로드하고 모든 센서의 값·단위·부팅 ID·GPS fix를 확인한다.
2. 52Hz IMU 저전력 모드의 실제 50Hz 목표 수신율과 정지/움직임 잡음을 확인한다. 필요하면 `IMU_LOW_POWER=false`로 정확도 우선 동작을 비교한다.
3. BLE 연결 간격/출력/광고 간격의 실제 적용 여부와 필요한 거리의 수신율을 측정한다. 최저 송신 출력은 손실률 기준을 만족하는 범위에서 결정한다.
4. I2C 소프트웨어 bit-bang의 CPU 소비를 더 줄일 수 있는 bounded hardware TWIM 구현을 검토한다. 시간 제한·DMA 종료·센서 분리 복구를 실물에서 검증하기 전에는 기존 버스를 대체했다고 완료 판단하지 않는다.
5. GPS 모델에 맞는 절전/갱신 주기 지원 여부와 재고정 시간을 확인한다. 하드웨어가 제공하지 않는 전원 제어를 코드에서 가정하지 않는다.
6. NU40 회로의 DC-DC 인덕터 구성을 확인한 후 내부 DC-DC 사용 여부를 결정한다. 회로 확인 없이 활성화하지 않는다.
7. 센서/USB/PC 반복 분리·재연결, UART 손상 입력, 장시간 운용, 메모리/스택 여유와 drops/gaps를 확인한다.

전류와 기능을 함께 측정하기 전까지 “최저 소비 전력 달성” 또는 “모든 하드웨어 기능 검증 완료”로 간주하지 않는다.

자료: [ST 데이터시트](https://www.st.com/resource/en/datasheet/lsm6ds3tr-c.pdf), 설치된 Adafruit nRF52 코어의 `bluefruit.cpp`, `FreeRTOSConfig.h`.
